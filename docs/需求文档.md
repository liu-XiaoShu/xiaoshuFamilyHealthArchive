# 家庭健康管理系统 — 需求规格说明

本文档描述当前已实现系统的**业务范围、功能与非功能约束、数据结构要点与接口概要**，并与仓库内前后端实现对齐；用于交付说明、局域网部署自检与后续迭代备忘。

---

## 1. 文档信息

| 项 | 说明 |
| --- | --- |
| 适用版本 | 以仓库当前代码为准（FastAPI + Vue 3 + SQLite） |
| 部署形态 | **单机或局域网**：浏览器访问；数据落盘服务端 |
| 用户模型 | **单管理员账号**登录后方可使用全部业务接口（局域网场景简化设计） |

---

## 2. 系统概述

### 2.1 建设目标

在**家庭或小范围局域网环境**内，集中管理家庭成员的**体检与健康检查数据**：维护成员档案、维护可自定义的检查指标体系、按**报告批次**录入或导入检查结果、多角度查看明细与历年趋势，并支持 **CSV 导出/导入**。数据仅存于服务端本地数据库文件中，辅以**登录会话**降低未授权访问风险。

### 2.2 技术架构

| 层级 | 技术 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3、Vite、TypeScript、Vue Router、Axios | SPA；开发时 `/api` 代理至后端 |
| 可视化 | Chart.js、date-fns、chartjs 插件（时间轴 / 标线等） | 趋势图表页 |
| 后端 | FastAPI、Starlette Session、SQLAlchemy 2、Pydantic v2 | REST API；SQLite 单机库 |
| 安全存储 | bcrypt（口令）、itsdangerous（会话 Cookie 签名） | 见下文认证 |

### 2.3 部署要求（概要）

- **推荐**：前端 `npm run build` 后，由后端挂载 `frontend/dist`，浏览器访问 **`http://<主机>:8000`**，前端与 **`/api` 同源**，Cookie 会话工作正常。
- **开发**：`./scripts/start-dev.sh` 同时启动后端 `:8000` 与前端 Vite `:5173`（`/api` 走代理）。
- 数据库文件默认路径：**`backend/data/family_health.db`**（可由 `backend/app/db.py` 推导）。

---

## 3. 术语与核心业务对象

| 术语 | 含义 |
| --- | --- |
| 成员（Person） | 家庭中的一个人及其档案与健康数据归属主体 |
| 报告批次（ExamSession） | 一次体检/检查对应的一个批次：**报告时间**、可选机构与批次备注 |
| 检查细项观测（Observation） | 隶属于某批次、绑定某指标的一次测量记录（含取值、参考、异常标记、影像学描述等） |
| 指标（Indicator） | **树形**：可有上级分组节点与下级**叶子细项**；实际录入仅能选**叶子节点** |
| 器官（Organ） | 与指标多对多关联；用于报告中按器官聚合展示与成员器官顺序 |
| 当前异常（Current abnormal） | 在自然年与健康规则下，当前仍被判为异常的**叶子指标**及依据说明（后端计算） |

## 4. 功能性需求

### 4.1 认证与访问控制

**需求 FR-AUTH-1** 用户提供账号、口令登录；会话保存在 **Cookie**（名 `fh_session`），服务端校验后允许访问业务 API。

**需求 FR-AUTH-2** 除公开接口外，其余 **`/api/*`（除健康检查及认证接口）** 均需已登录会话，否则返回 **401**.

**已实现接口概要**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/login` | 登录 |
| POST | `/api/auth/logout` | 登出 |
| GET | `/api/auth/me` | 当前会话（未登录时仍返回结构化 JSON，不要求 401） |
| GET | `/api/health` | 健康检查，无需登录 |

**需求 FR-AUTH-3（首次初始化）** 数据库无任何 `app_users` 记录时，启动流程创建默认管理员账号；默认用户名 **`admin`**、默认口令 **`family-health`**（须在正式环境改写）。

**需求 FR-AUTH-4（口令自救）** 支持环境变量 **`FH_FORCE_RESET_ADMIN=1`**：启动时将配置的 **`FH_ADMIN_USERNAME`**（默认 `admin`）口令重置为当前 **`FH_ADMIN_PASSWORD`**（或默认值）。开发脚本 `./scripts/start-dev.sh --reset-admin-password` 会为本进程设置该标志。

详细环境变量说明见 **`README.md`** 与 **`backend/app/settings.py`**（支持 `.env`）。

---

### 4.2 家庭成员管理

**需求 FR-PERSON-1** 维护成员：**姓名（必填）、性别、出生日期、家庭角色、备注**等；支持列表展示与跳转详情。

**需求 FR-PERSON-2** 支持**删除成员**（级联删除其所有报告批次及观测）。

**需求 FR-PERSON-3（列表辅助）** 列表可切换**「仅仍有当前异常的成员」**筛选（依赖后端下发的异常计数）。

**需求 FR-PERSON-4（头像）**  
- 可为成员上传头像（大小与类型后端校验），存储相对路径字段 **`avatar_rel_path`**。  
- 提供 **`GET /api/persons/{person_id}/avatar`** 读取媒体；无自定义头像时前端使用占位规则（缩写等）。  

**血型 / 身高 / 体重 FR-PERSON-5** 成员读写模型中的 **`blood_type`、`height_cm`、`weight_kg`** **不直接在档案表单中长期手填作为主来源**，而是由后端根据名为 **「血型」「身高」「体重」** 的检查细项在各报告中的取值，按**自然年优先、缺省则向前追溯**的规则解析回填至成员视图（参见 `person_report_vitals.py`）。

**需求 FR-PERSON-6（器官顺序）** 提供 **`GET /api/persons/{person_id}/organs`**：返回该成员适用器官序列（可按性别筛选系统器官；失败时回退到全局器官列表），供报告视图「按器官」排序使用。

---

### 4.3 报告批次（Exam Session）

**需求 FR-SESSION-1** 在成员下创建、列出、查看、修改、删除报告批次。

**需求 FR-SESSION-2** 批次字段：**报告时间 `report_at`（必选语义）**、机构、备注。

前端提供批次列表与 **`/persons/:personId/sessions/:sessionId`** 批次明细页。

---

### 4.4 观测记录（Observation）

**需求 FR-OBS-1** 单次观测隶属**一个批次**，绑定**叶子指标**，包含：`measured_at`、**`value_text`**、**`ref_text`**、**`abnormal`**、`remarks`、`findings_text`、`conclusion_text`（影像叙事类可用后二类字段）。

**需求 FR-OBS-2（列表接口）**  
`GET /api/persons/{person_id}/observations`  
支持查询参数：**`from` / `to`（测量时间区间）** 等；可用于前端分组（按器官 / 类型 / 时间在**前端**分组，不改变接口语义）。

**需求 FR-OBS-3（批次内录入）**  
`POST .../sessions/by-id/{session_id}/observations` 批量创建多条观测。

**需求 FR-OBS-4（校验）** 创建Observation时指标必须为**叶子**（后端校验），避免把分组节点当指标用。

---

### 4.5 指标体系与器官

**需求 FR-IND-1（指标树）** 指标字段包含：`name`、`category`、`parent_id`、`is_narrative`、`unit`、`ref_range_hint`；与器官多对多。

**类别 `category`** 取值：**`physical` | `lab` | `imaging`**（体格 / 检验 / 影像语义）。

**需求 FR-IND-2（CRUD）**  
- `GET /api/indicators` 支持筛选：**类别、器官、仅叶子、`search` 模糊、`limit`/`offset`**。  
- 创建、修改、删除指标；删除需满足业务约束（存在观测等指标若外键 **`RESTRICT`** 则不允许删除）。

**需求 FR-IND-3（器官）**  
- `GET /api/indicators/organs` 列表（按 `sort_order` 等排序）。  
- `POST /api/indicators/organs` 新增器官（同名校验）；字段含 **`gender_scope`（全体成员/男/女等语义）**、**`sort_order`**。

**需求 FR-IND-4（种子数据）** 应用启动时对**器官及部分指标**等进行种子写入（参见 `seed.py`），便于开箱即用。

---

### 4.6 导出（CSV）

**需求 FR-EXPORT-1** 支持按成员导出检查明细为 **UTF-8 CSV（带 BOM）**，便于 Excel 打开。

**需求 FR-EXPORT-2（筛选）** 支持可选条件（GET 查询或 POST Body，与实现对齐）：  
测量时间 **`from/to`**、批次报告时间 **`report_from/report_to`**；**多条件 AND**。

**需求 FR-EXPORT-3（列字段）** 导出列包括但不限于（与实现对齐）：`person_id`、`person_name`、`gender`、`birth_date`、`blood_type`、`measured_at`、`session_report_at`、`session_institution`、`session_notes`、`indicator_id`、`indicator_parent`、`indicator`、`category`、`indicator_unit`、`is_narrative`、`value`、`ref`、`abnormal`、`remarks`、`findings`、`conclusion`、`organs`（器官名聚合）等。

---

### 4.7 导入（CSV）

**需求 FR-IMP-1** 按成员：**`POST /api/persons/{person_id}/import/observations-csv`**，multipart **`file`** 字段上传 CSV。

**需求 FR-IMP-2（模板）** **`GET`** 同上路径 **template**，返回模版说明或可下载模版（以实现为准）。

**需求 FR-IMP-3（编码）** CSV 必须为 **UTF-8**（建议带 BOM）。

**需求 FR-IMP-4（列规则摘要）**

- **必填**：`report_at`（报告时间）；`indicator_id` 或 `indicator_name`。**同名叶子指标多条时**必须再提供 **`indicator_category`**（中英文类别枚举与 README 对齐）。  
- **批次**：`institution`、`session_notes`（及中英别名）。  
- **明细**：`value_text`、`ref_text`、`abnormal`、`remarks`、`findings_text`、`conclusion_text`、`measured_at` 等。**相同报告时间归为同一批次。**

导入逻辑与错误提示以实现与 `README` 「需求对齐摘要」为准。

### 4.8 前端页面与业务流程

以下路径均以**登录后**为准（`/login` 为登录页，`postLoginRedirect` 规则：**默认回 `/`**；仅在曾访问 **`/persons...`** 时恢复深层链接）。

| 路径 | 功能 |
| --- | --- |
| `/` | **家庭成员列表**；新增成员、筛选、跳转详情 |
| `/persons/:personId` | **成员详情**：批次与录入入口、体格摘要磁贴（异常/报告/趋势）、CSV 批量导入区块、单次录入会话等 |
| `/persons/:personId/sessions/:sessionId` | **批次详情**：该批次观测列表与维护 |
| `/persons/:personId/observations` | **报告详情**：多维分组浏览全部明细（可按异常筛选等） |
| `/persons/:personId/current-abnormals` | **当前异常专项视图**（数据源为 current-abnormals API） |
| `/persons/:personId/trends` | **历年记录与曲线**：选择叶子指标绘图；支持定量数值与定性等级趋势（实现含解析与刻度策略） |
| `/indicators` | **指标与器官编辑** |
| `/login` | 登录 |

**顶部导航**：家庭成员、指标编辑；显示当前用户名、退出登录。**Axios 携带 Cookie**；会话失效时跳转登录。

---

### 4.9 「当前异常」业务规则（概要）

**需求 FR-CA-1** 接口 **`GET /api/persons/{person_id}/current-abnormals`** 给出当前在自然年与健康规则下的**仍为异常**的叶子指标集合，并就每条给出**依据标签**（如本年复查 / 沿用往年等业务语义）。

**细则**以后端 **`current_abnormals.py`** 及成员列表计数聚合逻辑为准；成员卡片上的 **异常/正常计数** 与该项一致口径。

## 5. 非功能性需求

### 5.1 安全性与隐私

- **会话密钥**：正式环境必须配置足够长度随机的会话签名密钥（见 `FH_SESSION_SECRET` / `settings`）。  
- **口令**：出厂默认口令仅用于首轮登录；应采用强口令。**重置口令**仅能由掌握服务器环境变量的管理员触发。  
- **传输**：局域网 HTTP 部署时 Cookie 设为非 Secure；若在 HTTPS 后部署需在代码层评估 `https_only` 等会话参数。

### 5.2 数据与兼容性

- 数据存储：**SQLite 单文件**；结构演进靠启动时 **`create_all`** 与 **`migrate_sqlite_schema()`** 的轻量 `ALTER`。  
- 大版本结构调整可能需备份后重建库（见 README 说明）。

### 5.3 缓存与一致性

API 响应对 **`/api/*`** 施加 **`Cache-Control: no-store`**，避免 CDN/浏览器磁盘缓存导致的陈旧计数或列表。

### 5.4 已知范围外 / 未成需求

以下为当前实现边界，不作为已交付强制需求：

- 多租户、家庭成员级权限分级、审计日志；
- 云同步、多端实时协同；
- 指标或观测的版本历史与回溯撤销（除 CSV 导出备份外）；
- OpenAPI **`/docs` 是否与登录共用保护**——默认未与本需求逐项绑定。

## 6. 数据模型摘要（表级）

| 表 / 模型 | 说明 |
| --- | --- |
| `app_users` | 登录账号：`username`、`password_hash` |
| `organs` | 器官：`name`、`gender_scope`、`sort_order` |
| `indicators` | 指标树：`parent_id`、`category`、`is_narrative`、`unit`、`ref_range_hint` |
| `indicator_organs` | 指标—器官关联 |
| `persons` | 成员：`name`、`gender`、`birth_date`、`member_role`、`**vitals`**、头像路径、备注、`created_at` |
| `exam_sessions` | 批次：`person_id`、`report_at`、机构、备注 |
| `observations` | 观测：`session_id`、`indicator_id`、`measured_at`、取值与叙事等 |

外键语义要点：**观测指向指标删除为 `RESTRICT`**；观测与批次级联批次删除 **`CASCADE`**；成员删除级联批次等。

## 7. API 路由分层索引（`/api` 前缀补充规则）

以下内容便于对照代码，不设为独立「接口文档」替代品；详细参数可查阅各 `backend/app/routers/*.py` 或 Swagger（若启用）。

| 前缀/模块 | 主要内容 |
| --- | --- |
| `/api/auth/*` | 登录、登出、`me` |

| `/api/persons/{person_id}/export` | CSV 导出（GET / POST Body 筛选） |
| `/api/persons/{person_id}/import/observations-csv` | 模板 GET、导入 POST |
| `/api/indicators` | 指标 CRUD、`/api/indicators/organs` 器官 |
